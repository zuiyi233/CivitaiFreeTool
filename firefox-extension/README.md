# CivitaiFreeTool 扩展 1.4.0 · Firefox

## 安装 / 更新
本 ZIP 未签名：打开 about:debugging → 此 Firefox → 临时载入附加组件，选择 manifest.json。重启后需再次临时加载；永久安装需 Mozilla 签名。

## 发送当前页
先打开 CFT（推荐 v2.6.25）并在设置填写保存 Civitai API Key。点击扩展图标，在“当前页面”确认模型标题与链接，点“发送当前页到 CFT”。多文件选择在软件内完成。

## 批量标签页
1. 打开想下载的多个 C 站模型详情页，无需逐页点击扩展。
2. 打开扩展 → “批量标签页”。默认列出全部浏览器窗口的模型页，也可切换“当前窗口”。即使当前页不是 C 站，也能使用此入口。
3. 列表只列 C 站模型详情页。图片页、帖子页、`/models?types=…` 这类列表页、搜索页、个人主页、C 站 CDN 与所有非 C 站标签都不进列表，它们在下方汇总行里各自计数（“共 N 个标签页 · C 站 M · 可提交模型页 X · 未纳入提交 … · 非 C 站已忽略 W”），所以“筛掉了多少、为什么筛掉”看得见。
4. 可按类型 / 底模 / 补全状态 / 是否可提交筛选，按标题、类型、文件大小、下载量、发布时间、窗口排序，也可搜索模型名、ID、类型、底模或标签。
5. 初始全选；可取消不需要的页，或用全选按钮选择当前搜索结果。
6. 点“发送选中 N 项到 CFT”。关闭小窗不打断后台提交；重新打开可查看结果。不会关闭或切换你的标签页。
7. 小窗下方的“发送到 CFT 之后”显示软件里的真实状态（排队中 / 下载中 42% / 已完成 / 失败原因 / 落盘目录）。这份快照记在扩展存储里，关掉小窗再打开还能看到；CFT 没开着时它显示上次查到的状态并说明原因，不会当成“没有任务”。
8. 只有那里显示“已完成”才算下到本地。扩展“已提交”只表示软件接收了链接。

同模型同版本同文件 ID 的 red/com 重复页合并；不同版本 / 文件保留。一次最多 500 个不同条目。
未收到确认的条目会显示“待核对”，不会自动重发。先查看 CFT；如确需再次发送，点“清除提交记录（允许重新发送）”，此操作只清扩展记录，不删除 CFT 任务。

右键模型页或模型链接 → “发送到 CivitaiFreeTool”仍可使用。

## 模型信息补全
列表里的类型、底模、文件大小、下载量、发布时间、标签、缩略图来自 C 站公开接口（`/api/v1/models/{id}`、`/api/v1/model-versions/mini/{id}`、`/api/v1/images`）。每个标签页按**它自己的站点**取数：civitai.com 与 civitai.red 是两套独立数据，一边查不到不会拿另一边冒充。结果缓存在扩展存储里（默认 10 分钟），重开小窗先读缓存再联网。

> 这条缓存**在 Firefox 上可能不生效**：lib 走的是 `chrome.storage.*`，而 Firefox 的 `chrome.*` 命名空间是回调式的、不返回 Promise，`await` 会拿到 undefined，于是每次都重新联网（功能不坏，只是白打站点接口、更容易撞限流）。为了不跟 Chrome 版分叉代码，这里没有另写一套存储层，而是让界面**如实说出来**：缓存没生效时汇总行会显示"扩展缓存本轮没生效（每次打开小窗都要重新联网补全）"。看到这句就说明命中了这个已知差异。

取不到数据时行尾给状态徽章，各说各话，绝不塌成“没有数据”：
- **需登录态**：匿名请求被站点挡回，不代表这个模型不存在。
- **限流退避**：站点回了 429，本轮不再打它，退避到几点写在列表下方，点“刷新”即可重来。
- **本站不存在**：该标签页自己的站点上这个 ID 是 404，这一行会取消勾选资格。
- **取数失败**：超时 / 5xx / 应答不是合法 JSON；有旧缓存时仍显示旧值并标“旧缓存数据”。
- **未取数**：非详情页或站外地址，本来就不请求。

## 与 Chrome / Edge 版的能力差异
这个 Firefox 版**只做到“把勾选的模型链接交给软件”**。以下都是 Chrome / Edge 版才有，Firefox 里点了也不会发生任何事，所以界面上干脆没有这些按钮：

| 能力 | Chrome / Edge 版 | Firefox 版 |
| --- | --- | --- |
| 筛选列表 + 汇总行 + 信息补全 + 下载状态跟踪 | 有 | 有（同一份 `lib/tabrows.js`、`lib/enrich.js`，逐字节相同） |
| 一键归档 / 批量归档（封面、详情图、评论、提示词、模型信息存档到本地归档目录） | 有 | **没有**：Firefox 侧没有 `offscreen` 归档页面 |
| 归档在你关掉小窗后于后台继续 | 有（offscreen） | 没有 |
| 页面请求通道（借你已登录的 C 站标签页同源代发 GET，取评论 / 评价 / 受限样图提示词） | 有（注入 content script 到 C 站页面） | **没有**：本扩展不注入网页，因此这类数据在 Firefox 里拿不到 |
| 软件离线时降级用 `chrome.downloads` 写盘 | 有 | 没有（不申请 `downloads` 权限） |
| 侧边栏工作台（`sidePanel`） | 有 | 没有（Firefox 不支持该 API） |
| 模型页 / 图片页的下载徽章注入 | 有 | 没有 |

**评论与详情图归档只在 Chrome 版有，而且要求你在那个浏览器里已经登录 C 站**：这些内容站点只给登录态数据，扩展从不代你登录、也不读取你的 Cookie。想在 Firefox 里拿到同类内容是无解的，请改用 Chrome 或 Edge 版扩展。

Firefox 版能做到的富化，全部走公开接口 + 匿名请求（浏览器会带上你在 C 站的普通 Cookie，拿不到就如实标“需登录态”）；它不会因为拿不到评论就假装“这个模型没有评论”，因为它根本不提供评论归档。

## 隐私和权限
**不注入网页**。manifest 里没有 `content_scripts`，不申请 `scripting`、`offscreen`、`downloads`、`<all_urls>`；也没有任何页面内按钮或页面内请求通道。

**读取范围**：仅在主动打开扩展时读取标签页标题与 URL（`tabs` 权限）。过滤非 C 站模型 URL，并移除链接里的 token / 追踪参数。

**联网取数**：打开小窗时按每个标签页自己的站点向 `civitai.com` / `civitai.red` 的公开接口发 GET（`host_permissions` 只含这两站与 www 变体、以及 `127.0.0.1` / `localhost`），用于补全类型、底模、大小、下载量、标签与缩略图。请求头只有 `Accept`；**绝不携带 Civitai API Key、Authorization 头，也绝不读取网页正文**。扩展自己只连接硬编码的 `http://127.0.0.1:47531`，不访问其它本机端口。

**发给本机软件的内容**：只有用户勾选的模型 URL。不发送 Cookie、API Key、网页正文或未勾选的标签页。

**缩略图**：列表行的封面以普通图片方式从 `image.civitai.com`（C 站自己的 CDN）加载，图片地址来自上面那次公开接口应答。它不需要额外权限，但这条请求本身会让该 CDN 知道你打开了哪个模型的缩略图；介意就在 Firefox 里禁止扩展页面的远程图片，列表其余字段不受影响。

`storage` 权限保存：上一批的提交结果与重复发送保护、“发送到 CFT 之后”的状态快照、以及信息补全的缓存。`contextMenus` 提供右键“发送到 CFT”。
只获取此浏览器可访问的标签，不能跨 Chrome / Firefox 枚举；隐私窗口须在浏览器中明确允许扩展访问。
