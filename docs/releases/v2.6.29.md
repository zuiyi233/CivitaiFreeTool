# v2.6.29 · 模型示例图加载性能（视频误判 / 显示档 / 缓存 / 按需落盘）

「有些模型的图要 1 分钟甚至 5 分钟才出来」——排查结论是主因不在网络，在**我们自己把视频当图片处理**，以及缓存预算小到必然淘汰。这一版把四条都改了，并补了两处只有真跑起来才会暴露的前端缺陷。

## 先说结论：慢在哪里（真实库实测）

以你机器上的库为准（114 个模型、479 条 `info.json` 图片条目）：

| 现象 | 实测 |
|---|---|
| `images[]` 条目的 `type` 字段 | **100% 缺失**（只有 `url/width/height/nsfw`） |
| 因此被当静帧的 `.mp4` | **107 条（22.3%）** |
| 瀑布流拿到 `.../width=460/x.mp4` 的返回 | `content-type: video/mp4`，**1,283,945 ~ 2,314,133 字节**，`<img>` 永远解不出来但带宽已花掉 |
| 查看器拉视频 `original` 档 | 均值 **19,429KB** 下完交给 PIL 必然报错，个别还撞「超过 25 MB」 |
| 同一张 1920px 图：原图档 | 1,450,825 字节 / 2.75s |
| 同一张图：显示档 `width=1440,quality=80` | **94,168 字节 / 3.74s** |
| 磁盘缓存预算 vs 全库原图体积 | 1024MB vs 约 **3.3GB**（静帧 1.19GB + 视频 2.08GB） |
| 有 `<模型名>.images/` 目录的模型 | **0 / 161**（读盘通道一直空转） |

单轮计时没赢：链路吞吐实测在 **8.2KB/s ~ 1760KB/s** 之间抖，所以「这一次快了多少」不是这一版的收益点。收益在**尾部延迟**（不再有 19.4MB 的死下载）、**缓存容量**（看过一次的不再被 LRU 挤掉）、**重复查看**（本地优先，命中就是 0 网络）。视频帧现在 **0.016s、0 字节**返回明确文案。

## 改了什么

1. **视频不再冒充静帧**：判定改成「`type` 或 URL 尾缀」，并收敛成 `reverse_parse.is_video_image_entry` 一份实现。`gui` 的封面下载链路此前用的是只认 `type` 的那份，会把 mp4 直链当封面写出去——同一处一起修了。
2. **显示档降级 + 防上采样**：全库 479 条 `width` 都在（median 1080），其中 **328 条（68%）本来就 ≤1440px**，无脑请求 `width=1440` 是上采样——实测一张 682KB 的窄图被顶成 1,218,800 字节，比不降级还大。规则是按条目实际宽度收口：`natural_width <= max_width` 就不发 `width=`。CDN 实测**忽略** `format=` 与 `resize=`（返回体字节数与不带时一致），所以只用 `width=`/`quality=`。
3. **分档缓存 + 预算扩容**：缓存键按档位分（`':w1440q80'` 之类后缀），显示档请求绝不会命中原图档条目；默认键与旧实现**逐字节相同**，老缓存不作废。`gallery_cache_mb` 默认 **1024→8192**，可配上限 **8192→65536**。
4. **体积上限与总时限**：新增 `image_max_mb=20` / `video_max_mb=100` / `fetch_deadline_s=120`，并让 `webui` 与 `image_gallery` **共用同一实现**（此前同一配置键两处各钳一套：负值一处回默认、另一处钳成 1MB；`normalize` 允许到 2000/4096 而运行时钳到 1024，用户调大被静默截断）。`fetch_deadline_s` 是 wall-clock 总时限，原来的 `timeout=25` 是 socket 级，慢流能挂几分钟。
5. **按你要求把图拉进模型目录**：打开详情后按需把缺的帧补到 `<模型名>.images/`——同时只 1 个任务、任务内串行 1 张、已存在即跳过、可取消、磁盘余量不足就跳过并写明原因；轮播与详情的帧来源由「远程优先」改成**本地优先**。自动补帧每个模型最多落 3 个 mp4（与既有 `_ensure_local_videos` 同口径），要全量视频用详情里的「下载全部图片」。
6. **查看器如实标注**：`width=/quality=` 转码会剥掉 EXIF 与 UserComment，所以显示档字节绝不用于提取生成参数，取不到就退回 `info.json` 的 meta 并标注「生成参数未从原图读取」；**保存图片与复制图片仍走原图档**。

## 这一轮实测才抓出来的两处前端缺陷

- **关掉「瀑布流自动轮播」后，卡片停在最后一帧不动**：`_mmAutoSetInterval(false)` 原来只 `clearInterval`，停下一次心跳，但自动播放器已经挂上的叠帧留在 DOM 里；`_mmAutoTick` 又在开关关闭时提前 return，回收逻辑（`_mmAutoSweep`）永远轮不到。实测关掉后 2 张非悬停卡片各剩 1 层叠帧，要等 hover 或重渲染才消失。现在关的时候把 `_autoPlayers` 里的卡片逐个 `_stopCarousel` 收干净，设置项的即时生效路径也接上了这个函数。
- **「真淡入」其实没有淡**：v2.6.28 把写法改成「先以 `opacity:0` 插入、下一帧再抬到 1」，方向对但少了一步——刚插入的元素在这一帧之前**没被算过样式**，浏览器没有「变化前样式」可比，rAF 里改 `opacity` 被当成初始值直接落到 1，过渡整体跳过。实测 computed opacity 从 `1` 起步。现在 append 之后先读一次 `getComputedStyle(el).opacity` 强制那次样式计算，淡入才真的存在（回归用例断言起始值 <0.9 **且**过程中出现 intermediate 值，防止退化成延迟硬切）。

## 落盘链路的四条 P2 收尾

复核提的四条押后项一并补上，都落在「往用户模型目录写文件」这条链路上：

- `gui._download_image`（设为封面 / 封面下载的落点）此前直接 `r.read()` 整段读，既不计量也无墙钟截止——一条伪装成 `.jpg` 的 mp4 慢流就能吃满内存并把后台线程挂住几分钟。改为复用 `image_gallery.static_limit_bytes` / `fetch_deadline_seconds` 同一份档位（Content-Length 预检 + 分块上限 + monotonic 截止），不新写第二套钳制。
- `set_model_cover` 此前没走补帧那套守卫。`<名>.images` 做成指向别处的 junction 时，`os.path.islink()` 恒为 False、realpath 的「同层」校验照样通过，封面会顺着链接写到模型目录之外；现在下载前拦目录、落点再拦文件与目录，拒绝时给中文提示且零外部写入。
- 写盘的 `.tmp` 改独占创建，但**只拒目录与链接**：上次中断留下的普通 `.tmp` 必须清掉重来，一律拒绝会让那一张图永远补不进去（补帧每次打开详情都会重试同一批目标）。失败路径原先那句无条件 `if os.path.exists(tmp): os.unlink(tmp)` 更糟——它会把独占创建刚拒掉的别人的文件直接删掉，守卫沦为静默删除；现在只清自己创建的那个 fd。
- `download_all_images` 把「已存在」并进「新下载」虚报数量；现在 `downloaded` 只计本次新下、`existing` 单列，前端文案改成「示例图：新下载 X 张，已存在 Y 张」。进度条本身走 `done/total`，不受影响。

本机没有创建文件符号链接的权限（需开发者模式或管理员），`.tmp` 是符号链接那条用例在这台机器上跳过；目录形态与残留普通文件两条都跑了真断言。

## 回归用例本身的问题（说明「为什么之前没跑到」）

`tests/test_masonry_carousel.cjs` 的「约 3 秒/帧应至少换过一次帧」一直误报。逐项排除后确认是用例采样口径错了，不是产品不换帧：叠帧是 `append` 上去的，淡入交叉期 DOM 里同时有旧新两张，`querySelector('.ms-img-alt')` 取到的**第一张是还没摘的旧帧**，于是把「已经换帧」采样成「没换」。同批还修了这几处用例自身的问题：

- 缺 `switchPage('models')`：`index.html` 默认 active 标签是「批量下载」，`#page-models` 处于 `display:none`，卡片全是零尺寸，`waitForSelector` 只能等到超时（这一条在 `532915c` 上以同样方式失败，属于既有用例缺陷）。
- 慢网孤儿图用例里的帧必须是**远程 URL**：`data:` 帧在 `_carouselAdvance` 走「本地 b64 立即可用」的直挂分支，根本不经过 `new Image()` 预载，「预载未回来前不该有叠层」这条断言当时恒不成立。
- 淡入探针的采样窗口 14 帧（≈0.23s）比 0.35s 的过渡短，「收敛到不透明」不可能成立；改 30 帧跨过过渡期。
- 「整个网格叠层清零」这类断言与自动轮播共存时不成立（自动节拍会在别的卡片合法挂帧），相关检查点先关掉自动轮播。
- `tests/test_ui_preferences.cjs` 的 `.nav-tab .ic` 写死 7，而本仓库多了一页「资源库」实际是 8；改成核对页签集合，不再靠魔数。

## 已知代价与可调项

- 静帧上限从旧的 25MB 收到 **20MB**：本地 20–25MB 的原图会改判「图片超过 20 MB」，调 `image_max_mb` 即可恢复。
- `images_dir_autofill` 默认**开**：这是往你的模型目录写文件（打开详情触发）。不想让软件动模型目录就在设置里关掉，或点详情进度行里的取消；关闭只影响后续补帧，已落盘的帧保留。
- 缓存默认 8GB：全库原图约 3.3GB，8GB 才谈得上「看过一次就不重拉」；磁盘紧张就在设置里调小（下限 64MB）。
