# v2.6.31 · 扩展↔桌面端链路修通，评价/评论回到归档里

这一版只追一件事：**以前油猴脚本能下载评论、详情图和提示词，做成桌面端 + 浏览器扩展之后不行了**。逐条实测下来，这不是一个 bug，是四个互不相干的洞。

## 实测：四个洞分别是什么

| 现象 | 实测到的原因 |
|---|---|
| 扩展点"发送当前页到 CFT"没反应 | 桥固定按 `fn(url, dest_subdir)` **两参**调用处理函数，注册方只收一参 → 每次 HTTP 500。自 5ba4e53 起一直如此，注册函数换过一次而注释没跟上，所以看着像"接口挂了" |
| 评论、评价整块没有 | 桌面端从来没实现过评论/评价抓取（只做了 `/api/v1/*` 公开接口）；扩展侧则把请求从页面搬进 offscreen 后**丢了登录上下文**，tRPC 回 401、公开 API 回空 items |
| 部分示例图没有提示词 | 官方 `/api/v1/images` 的过滤是 `browsingLevel ?? nsfw ?? publicBrowsingLevelsFlag`，**带 API Key 也默认只放行 PG**。同一张 Soft 图实测：`browsingLevel=1 → items=0`，`=31 → items=1` |
| 镜像站（civitai.red）上取到错的数据 | 单图归档的请求链路里没人带发起页 URL，站点判定退化成默认 `civitai.com`，于是 red 的图页真的向 com 发了跨站请求（跨站时 `credentials:'same-origin'` 等于不带 Cookie），却被记成"页面通道 · 带你的登录状态" |

## 你会看到什么变化

**1. 下载完成就多一个 `_评论.txt`。** 桌面端用自己保存的 Civitai API Key 直连 C 站取评价/评论，落成 `<模型名>_评论.txt`，和模型一起移动、进回收站、更新时替换。实测某个模型版本拿到 **67 条评价**（接口报 `totalItems=67 / totalPages=2`，两页拿全）。文件里会写清数据是哪条通道给的、拿了多少条、翻页有没有截断，只打分没写字的评价标成"(只打了分，没有写文字评价)"，不会伪装成空条目。

**2. 扩展的评论/提示词改走"你已登录的那个 C 站标签页"。** 之前判定"站点关闭了内部 tRPC"是错的：被拒的是**没有请求上下文的裸请求**，丢的是登录态不是功能。现在扩展会请你打开着的 C 站页面同源代发一次只读 GET（白名单只允许 `civitai.com|civitai.red` 的 `/api/v1/*` 与 `/api/trpc/*`，单条响应上限 3MB，超时即丢，不跟随重定向），拿不到才回落直连，并且**把当次实际走的通道如实写进产物**。同时把入参按站点当前 schema 全部重写（`entityType` 必须小写、第一页不能带 `cursor:null`、不给 `repliesDepth` 就永远没有回复、评价按 `page` 翻页且 `modelId`+`modelVersionId` 必须同传）。

**3. 弹层不再把所有标签页倒给你。** 列表只列 C 站模型页，汇总行把筛掉了多少说成事实：`共 4 个标签页 · C 站 3 · 可提交模型页 3 · 重复合并 1 · 非 C 站已忽略 1 · 跨 2 个窗口`。每行补上类型、底模、版本名、文件大小、缩略图；`需登录态`、`限流退避`、`本站 404`、`取数失败`、`旧缓存值` 各自成徽章，**不会塌成"没有数据"**；联网没回来时列表也不会空。

**4. "发送到 CFT"之后能看到结果了。** 新增任务区，显示你提交的那几个模型在软件里的解析与下载状态：排队中 / 下载中（百分比 · 已下 MB · 速度 · 落盘目录）/ 已完成 / 失败。快照存在扩展自己的 storage 里，**关掉小窗再打开还在**；"扩展已提交"和"CFT 已下载完成"在界面上是两件事，不再混为一谈。

**5. 两个显示层的坑**：归档状态面板以前会把"拿不到状态"渲染成"共 undefined 页 · 完成 0 · 跳过(已归档) 0"，把一次通信故障说成你的归档结果；扩展 README 里"不注入网页"的声明自 2.1.0 起就不成立，已按事实重写（注入范围、页面代发通道、发给本机软件的内容都逐条写清，仍然不发送 Cookie 与 API Key）。

## 已知边界（说清楚，别当成坏了）

- **评论正文需要你真的登录着 C 站，API Key 也不行。** 带 Key 对 `model/image/post/article/review` 各种 `entityType` 的评论计数一律返回 0，v1 评论接口线上 404；未登录时模型页 DOM 连 Comments 标签都不渲染。所以**纯桌面端流程只保证评价**，评论要走扩展 + 已登录标签页。而且要如实说：**"登录会话能拿到非空评论正文"这一跳，本次仍然没有被任何路径实测证实**——验证它需要一个已登录的 C 站标签页。产物文案按这个口径写，不会承诺"已拿到全部评论"。
- 评价翻页固定 5 页 × 50 条 = 250 条。热门版本实测有 18481 条，超出时文件里写"站点共 N 条，本次只保存前 250 条"，不会假装拿全了。
- 按 C 站名称改名时，`_评论.txt` 不会跟着改名（改名逻辑在另一模块里），会留在旧名前缀下。
- 不做历史回填：只有**新完成**的下载才会生成评论文件。
- 批量归档进行中，图片页上的 SAVE 按钮会提示"归档任务进行中，请稍后再归档这张图"——这是为了不让两个任务共用同一条数据通道，没有做排队。

## 升级方式

只替换 EXE，配置、任务、历史与缓存都保留。浏览器扩展要**重新加载一次**（`chrome://extensions` → 重新加载；Firefox 走 `about:debugging` 临时加载）：Chrome 扩展版本 2.1.0 → 2.2.0，Firefox 侧同步了筛选、元数据富化与任务区，但**归档类能力（一键归档 / 批量归档 / 页面代发）仍只有 Chrome 版有**——Firefox 没有 offscreen 文档，差异列在 `firefox-extension/README.md`。
