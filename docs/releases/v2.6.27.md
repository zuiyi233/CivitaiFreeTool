# v2.6.27 · 资源库（ComfyUI 生成图 / 视频）

把 ComfyUI 产出的图片和视频纳入本程序管理，与模型库并列成一个新页「资源库」：按类型 / 底模 / LoRA / 文件夹 / 标签筛选，可搜索提示词，可打标签收藏，视频直接播放。对既有代码只动了两处——`scan_models` 加 3 行与资源库扫描的互斥守卫、`APP_VERSION` 递增，其余全是新增（`git diff webui.py` 为 409 增 / 1 删），模型库功能零改动。

## 怎么用

1. 设置 → 资源库目录：填 ComfyUI 的 output 目录（每行一个，可多根，支持局域网共享路径），旁边有「自动探测」按钮。可填排除目录（相对根，含子目录生效）。
2. 打开资源库会自动增量扫描；之后每次进页只在距上次扫描 60 秒以上时重扫，扫描中可随时停止。
3. 网格卡片：图片直接出缩略图，视频进视口才挂载播放并自动抓首帧缓存（下次直接读缓存，不再起流）。点卡片看详情。
4. 筛选：类型 / 底模 / LoRA / 文件夹（含目录树面板）/ 标签 / 仅收藏 / 仅无元数据；顶栏有关键词搜索、排序、分组（按日期 / 底模 / 文件夹）。
5. 详情：大图或视频播放 + 全部生成参数（种子 / 步数 / CFG / 采样器 / 调度器 / 尺寸 / 时长 / 元数据来源）。模型引用可点：在本地模型库里定位到就直接跳模型详情。动作有收藏、打标签、复制提示词 / 路径、打开所在文件夹、送工作流分析、送逆向解析、删除（进回收站）。
6. 删除只回收媒体文件本体，**不会**连带同名的 `.json` 工作流边文件——ComfyUI 让 `out.png` 和 `out.mp4` 共用同一个 `out.json`。

## 实现要点

- **单文件不背 ffmpeg**：图片元数据读 PNG 的 tEXt / zTXt / iTXt 块（流式，命中即停）；视频元数据纯 stdlib 解析 mp4 atom（`moov → udta`，兼容容器级与轨道级 `©cmt` / `meta·ilst`），因为 ComfyUI SaveVideo 与 VHS 都把 `{"prompt":…,"workflow":…}` 写进 comment 标签。moov 常在文件尾（默认不 faststart），所以读首尾各 16MB 窗口而不是整文件。
- **索引是本地 sqlite**（`media_library.db`，stdlib，无新依赖）：条目表 + 标签表 + FTS5 全文；几万条目不卡，缩略图与模型封面共用同一套缓存。增量对账按 mtime+size，只有变化才重新解析；文件消失只打 `missing_since` 标记，30 天后才清行，目录读不出来时**不**误判为已删除。
- **底模 / 提示词按字段名回收**：现代工作流走 `SamplerCustomAdvanced` + `BasicGuider.conditioning` + 自定义节点，标准「从 KSampler 顺链回溯」提不出提示词也分不出底模。新增纯字段名兜底（底模看 `ckpt_name|unet_name|diffusion_model`，LoRA 看 `lora_name|lora_*|*_lora`，文本看 `prompt|text|caption|positive_text` 并跳过便签 / 常量 / 表达式类节点），只在顺链为空时生效，并且**照实标注来源**（详情里显示「按字段名提取」）。不猜未知节点语义，也不据此伪造负面提示词。
- **列表作用域由服务端定**：查询与分面只覆盖**当前配置在 `media_roots` 里**的目录。把某个目录移出设置，它的记录只是不再出现在网格和计数里（行保留，标签 / 收藏不丢），重新加回即恢复；前端传什么 `root_ids` 都会被服务端覆盖，不能自行放宽范围。
- **浏览器模式视频**：`GET /api/media?p=` 支持 Range / 206 / 416 流式，只允许配置的媒体根之内的白名单扩展名（两侧都做 `realpath` 归一，防符号链接逃逸与同前缀兄弟目录）；`file:///` 只在窗口模式用。

## 实测（用户真实库：2792 个在库条目，2260 图 / 532 视频，4.7GB）

| 项 | 结果 |
|---|---|
| 首次全量解析 | 约 7 秒 |
| 增量重扫（无变化） | 0.2–2 秒 |
| 列表页（250 条 + 分面 + 分组） | ~110ms |
| 分面聚合 / FTS 搜索 | ~100ms / ~50ms |
| 视频页并发流 | 250 张卡从 ~200 路 `/api/media` 并发降到 1 路（懒挂载 + 滚远释放） |
| 元数据覆盖（字段名回收前 → 后） | 提示词 29% → 65%，底模分类 46% → 68%，LoRA 27% → 49%，distinct 底模 21 → 32，mp4 提示词 0/426 → 354/426 |

## 验证

- 后端：180 项新增用例（元数据 61 / 索引与扫描 67 / RPC 层 27 / 流式端点 25），全量 578 项通过（本功能前基线 398 项），`node --check` 与 `py_compile` 全通过。
- 安全面复核（独立复核代理）：XSS（恶意 PNG prompt 走完 extract → sqlite → RPC → 前端，所有 innerHTML 落点均转义）、`/api/media` 路径穿越与符号链接逃逸、Range 边界（空文件 / 多区间 / 起点超界 → 416）、SQL 注入面（sort/group 白名单、IN 占位符、LIKE 转义 `%_`）、扫描对账「目录不可读不判缺失」。
- 界面：真实浏览器（Edge/Chromium 内核）驱动 47531 端口的浏览器模式实例走查——扫描进度、网格与缩略图、类型 / 底模 / 标签 / 仅收藏 / 仅无元数据筛选、关键词搜索、分组标题、标签建 / 改 / 删、收藏、详情视频播放与 seek（实测 206）、模型引用跳转与未命中提示、分页续拉、设置项生效（`media_page_size` 改 250 后每批 250）。控制台无报错。
- 两种界面模式都验过视频首帧回传：浏览器模式同源直接落盘（实测缓存 23 张海报）；窗口模式（`file://` 页面 + `file:///` 视频）用等价探针确认 Blink 不因跨源污染挡掉 canvas，无需另设通路。
- 冻结产物复验（打包后的 EXE，版本资源同步到 2.6.27）：在临时目录用真实配置的只读副本起浏览器模式实例，进资源库自动增量重扫得「新增 0 · 更新 0 · 共 2792」，首屏 200 卡，控制台仅字体 `Slow network` 提示、无 error。这一轮同时抓到并修掉了「移出配置的根目录仍留 3 行幽灵卡片」的作用域缺陷（见上）。
- 局限说明：本次在自动化内置浏览器里 `visibilityState=hidden`（视口高度 0），截图与「IntersectionObserver 真实进视口」这一步无法验证，懒挂载改用结构证据（250 张卡全部只有 `data-src`、`src` 数为 0、`/api/media` 请求数 0，手动 hydrate 后 readyState=4 且解码出 832×480 首帧）。像素级观感需人工开一次窗口确认。
- 测试数据：只用合成 PNG / mp4 字节与临时目录；真实库只读扫描，未删除任何用户文件。
