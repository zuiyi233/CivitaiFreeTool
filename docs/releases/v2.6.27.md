# v2.6.27 · 资源库（ComfyUI 生成图 / 视频）

把 ComfyUI 产出的图片和视频纳入本程序管理，与模型库并列成一个新页「资源库」：按类型 / 底模 / LoRA / 文件夹 / 标签 / 采样器 / 调度器 / 尺寸 / 时长筛选，可搜索提示词，可打标签收藏，可批量操作，视频直接播放。对既有代码只动了两处——`scan_models` 加 3 行与资源库扫描的互斥守卫、`APP_VERSION` 递增，其余全是新增（累计 `git diff webui.py` 545 增 / 1 删，`browser_bridge.py` 243 增，`web/app.js` 1815 增），模型库功能零改动。

## 怎么用

1. 设置 → 资源库目录：填 ComfyUI 的 output 目录（每行一个，可多根，支持局域网共享路径），旁边有「自动探测」按钮。可填排除目录（相对根，含子目录生效）。
2. 打开资源库会自动增量扫描；之后每次进页只在距上次扫描 60 秒以上时重扫，扫描中可随时停止。
3. 网格卡片：图片直接出缩略图，视频进视口才挂载播放并自动抓首帧缓存（下次直接读缓存，不再起流）。点卡片看详情。
4. 筛选：类型 / 底模 / LoRA / 文件夹（含目录树面板）/ 标签 / 采样器 / 调度器 / 尺寸 / 时长区间 / 仅收藏 / 仅无元数据；顶栏有关键词搜索、排序、分组（按日期 / 底模 / 文件夹）。采样器、调度器、尺寸是三组可多选的 chip，带条目计数。
5. 详情：大图或视频播放 + 全部生成参数（种子 / 步数 / CFG / 采样器 / 调度器 / 帧率 / 尺寸 / 时长 / 元数据来源）。模型引用可点：在本地模型库里定位到就直接跳模型详情。动作有收藏、打标签、复制提示词 / 路径、打开所在文件夹、送工作流分析、送逆向解析、删除（进回收站）。`←` / `→` 或详情头的两个圆按钮在当前页内逐件翻页（到头就停，标题里写清是「当前页内序号」）。长提示词默认只露三行，真的没露全才在正文下方挂「展开全文（共 N 字）」，点一下松开到窗口高度上限（再点收回，没看全就在块里滚动），翻页换条目自动回到折叠态。
6. 批量：工具栏「多选」打开后卡片左上出勾选框，单击切换、Shift 范围选，可「选中当页已加载 N 项」或「选中筛选结果全部」（服务端分页，前端按 500 一批把 id 拉全，再点一次即停止）。操作条支持收藏 / 取消收藏 / 加标签 / 摘标签 / 送逆向解析 / 送工作流分析 / 删除，选择跨页、跨筛选保留；单次上限 2000 项，前端按 500 一片分片并播报「已处理 x/y」。
7. 收藏与标签可以带走：工具栏「导出标注」存一份 JSON（只含人工标注，不含机器解析的元数据），「导入标注」先试算再确认写入——匹配数、要收藏数、标签关联数、新建标签数、认不出数、有歧义数逐项报给你看。**导入只新增，绝不取消或删除你已有的任何标注**；认不出的条目原样跳过并说明原因。
8. 删除只回收媒体文件本体，**不会**连带同名的 `.json` 工作流边文件——ComfyUI 让 `out.png` 和 `out.mp4` 共用同一个 `out.json`。

## 实现要点

- **单文件不背 ffmpeg**：图片元数据读 PNG 的 tEXt / zTXt / iTXt 块（流式，命中即停）；视频元数据纯 stdlib 解析 mp4 atom（`moov → udta`，兼容容器级与轨道级 `©cmt` / `meta·ilst`），因为 ComfyUI SaveVideo 与 VHS 都把 `{"prompt":…,"workflow":…}` 写进 comment 标签。moov 常在文件尾（默认不 faststart），所以读首尾各 16MB 窗口而不是整文件。
- **索引是本地 sqlite**（`media_library.db`，stdlib，无新依赖）：条目表 + 标签表 + FTS5 全文；几万条目不卡，缩略图与模型封面共用同一套缓存。增量对账按 mtime+size，只有变化才重新解析；文件消失只打 `missing_since` 标记，30 天后才清行，目录读不出来时**不**误判为已删除。
- **webm / mkv 也读得动了**：补一层纯 stdlib 的 EBML 流式解析（变长元素 ID 与变长长度、`Info→TimecodeScale×Duration` 出时长、视频轨 `DefaultDuration` 出帧率、`Video→PixelWidth/Height` 出宽高、`Tags→SimpleTag` 里 `comment` 的那段 `{"prompt","workflow"}` 走**和 mp4 完全同一个后处理入口**，只在来源标记上区分成 `ebml_tag`）。两处规范细节是实测才试得出来的：`Tracks` 是 `0x1654AE6B`、`Tags` 是 `0x1254C367`（按记忆写成 …67 / …0x1254C076 时真实文件一个轨一个标签都读不到），`DefaultDuration` 单位是**纳秒**（`fps = 1e9 / DD`；按微秒算会得到 0.008–0.024 这种荒谬值，且旧的范围检查还挡不住）。`Duration` 的浮点宽度 4 / 8 字节都要撑住，未知长度的 Cluster 逐子元素走并有元素数与读取字节双上限。
- **底模 / 提示词按字段名回收**：现代工作流走 `SamplerCustomAdvanced` + `BasicGuider.conditioning` + 自定义节点，标准「从 KSampler 顺链回溯」提不出提示词也分不出底模。新增纯字段名兜底（底模看 `ckpt_name|unet_name|diffusion_model`，LoRA 看 `lora_name|lora_*|*_lora`，文本看 `prompt|text|caption|positive_text` 并跳过便签 / 常量 / 表达式类节点），只在顺链为空时生效，并且**照实标注来源**（详情里显示「按字段名提取」）。不猜未知节点语义，也不据此伪造负面提示词。
- **生成参数也按字段名回收**：提示词回收只解决了「写了什么」，参数位还是空的——`SamplerCustomAdvanced` 类工作流不走 KSampler 顺链，实测 seed 只有 19%、步数 / 采样器 / 调度器 37%、**视频五项全空**。补一层同样的纯字段名兜底（`seed|noise_seed|rand_seed|random_seed`、`steps|num_steps|sampling_steps|step_count`、`cfg|cfg_scale|guidance_scale|true_cfg_scale`、`sampler|sampler_name|sample_type|solver`、`scheduler|noise_schedule|schedule`），带值域校验，采样器 / 调度器**只认表内的值**（表由真实库实测值 ∪ ComfyUI 官方枚举构成）；同名的有效值出现两个以上就不选边、留空并在备注里写明「工作流里有 N 个不同的 X，未按字段名猜测」。链式给的一律不动。
- **视频帧率**：mp4 逐轨配 `mdhd` 时间基与 `stts`（`fps = 采样数 / (Σcount×delta / timescale)`，一条 entry 描述 count 个间隔，只加 delta 会把帧率算虚高），保留 3 位；拿不到就留空，**不默认 30**。畸形 `entry_count` 封顶 10 万，不让一个 4 字节声明吃掉扫描线程。
- **索引 schema v2 + 升级自愈**：参数从 `extra_json` 提到列上（`seed/steps/cfg/sampler/scheduler/fps`，`user_version=2`），v1 库打开即 `ALTER TABLE` + `json_extract` 回填（0.36 秒，逐列核对老列一列未变，**不需要删库重扫**）。但增量扫描按 mtime+size 对账，文件没改就永不重解析，新字段会永远空着——所以记 `extract_version`，落后时把老行标成待重解析、只在一轮完整扫描后落盘版本（真实库补解析 2035 行 / 31 秒，第二轮 182 毫秒空转，之后覆盖率与全新库逐字段相等）。迁移还顺手修了一个真缺陷：v1 库先有行后建 FTS 表时索引是空的，重解析的 UPDATE 触发器会直接 `database disk image is malformed`。第三轮的版本（`EXTRACT_VERSION = 3`，只改了 webm / mkv 的解析）不再拖着整库重扫——版本表声明了「这一版只影响哪些扩展名」就只 `WHERE ext IN (...)` 定向标记（真实库 0 个 webm / mkv，整库重解析实测是 2035 行 / 31 秒的纯浪费）；跨过的版本里只要有一个是整库级改动，仍旧退回整库口径，宁可多标不可漏标。
- **目录搬家不再丢策展**：条目身份是绝对路径 + 根目录哈希，而库目录名常带版本号（`ComfyUI_Mie_2026_V8.0`）。改名 / 换盘符后，若旧路径的文件确已不在、新根里有相对路径 + 大小 + 扩展名全等且唯一对上的条目，就把收藏与标签**复制**过去（旧行保留，加回即恢复的语义不破）；一个旧行对上多个新行、或反过来，一律不猜。
- **标注导出 / 导入**：档案身份键用「库内相对路径 + 文件大小」而不是绝对路径，所以搬家 / 换机后仍能认回来；标签父级用祖先名字**列表**而不是 `"父/子"` 串（标签名本身可以含 `/`，拼串会拆错层）；`dry_run` 与真写的计数口径严格一致（预览少报就是骗人）。
- **翻页不重算分面**：分面聚合带根作用域时真实库要 130ms，是整页耗时的主要来源；续拉分页传 `with_facets=0` 直接跳过，实测整页从 190ms 降到 45ms。给分面加 `(root_id, 列)` 复合索引实测只把 133ms 降到 128ms（噪声级），没做。
- **分面没露全要说出来**：采样器 / 调度器 / 尺寸三组是两行封顶 + 组内滚动，真实窗口 1266px 下尺寸组 37 个值只露出 2 个、滚动条几乎看不见。改成渲染后量一次真实溢出，只有真的没露全才在组尾挂「展开（共 N 项）」，点一下松开高度、再点变「收起」；控件挂在组上而不是滚动容器里（挂在容器内它自己就落在折行以下）。展开的那一组独占一行（挤在三列里展开会竖成一列，比折叠态更难扫），上限按窗口高度给（`min(60vh, 560px)`，超出仍在组内滚动，提示文案里写明）。实测：1266px 真实窗口展开后 37 个尺寸值全部露出、折叠后回到原布局；792px 窄窗口折叠态只露 2 个、展开后还有 9 个需要滚动（提示文案如实说明）。没溢出的组不挂任何多余控件（采样器 4 个值、调度器在宽屏下都不挂）。键盘 `Enter` / `Space` 与鼠标同权，重绘后焦点接回同一个控件。
- **长提示词同一条规矩**：详情里的提示词以前塞在共享类 `.detail-desc` 的 180px 固定高滚动框里——全文其实在，但没人知道能滚。资源库自己套一层 `.lib-desc`（**不动模型库共用的那个类**），折叠成约 3 行，量到真的溢出才在正文下方挂「展开全文（共 N 字）」，展开态高度按窗口给上限（同样 `min(60vh, 560px)`）+ 块内滚动，所以按钮提示里写的是「没看全就滚动」而不是「展开即全文」。两个容易踩的坑：必须在详情浮层已经显示之后量（隐藏态 `scrollHeight` / `clientHeight` 都是 0，会判成「没溢出」而永远不挂控件）；内嵌字体替换会改行高，所以 `document.fonts.ready` 之后按同一判定重测一次，且带请求令牌——用户已经翻页或关掉详情就不动现在的 DOM。展开态按条目 id 存，翻页与重开都回折叠态。实测：3464 字条目折叠 `70 / 1497` → 展开 `403 / 1497`，418 字条目 `70 / 187` → `187 / 187` → 再点回 `70`，36 字条目与无提示词条目都不挂控件。
- **列表作用域由服务端定**：查询与分面只覆盖**当前配置在 `media_roots` 里**的目录。把某个目录移出设置，它的记录只是不再出现在网格和计数里（行保留，标签 / 收藏不丢），重新加回即恢复；前端传什么 `root_ids` 都会被服务端覆盖，不能自行放宽范围。
- **浏览器模式视频**：`GET /api/media?p=` 支持 Range / 206 / 416 流式，只允许配置的媒体根之内的白名单扩展名（两侧都做 `realpath` 归一，防符号链接逃逸与同前缀兄弟目录）；`file:///` 只在窗口模式用。

## 实测（用户真实库：2792 个在库条目，2260 图 / 532 视频，4.7GB）

| 项 | 结果 |
|---|---|
| 首次全量解析 | 约 7 秒 |
| 增量重扫（无变化） | 0.2–2 秒 |
| 列表首屏（200 条 + 分面） | 190 ms |
| 列表续拉（跳过分面） | 45 ms |
| 分面聚合（带根作用域）/ FTS 搜索 | 130 ms / ~50 ms |
| 视频页并发流 | 250 张卡从 ~200 路 `/api/media` 并发降到 1 路（懒挂载 + 滚远释放） |
| 元数据覆盖（字段名回收前 → 后） | 提示词 29% → 65%，底模分类 46% → 68%，LoRA 27% → 49%，distinct 底模 21 → 32，mp4 提示词 0/426 → 354/426 |
| 参数覆盖（回收前 → 后） | seed 19% → 68%，步数 37% → 59%，采样器 37% → 62%，调度器 37% → 59%，**视频帧率 0/532 → 532/532**；CFG 保持 46%（现代工作流图里没有 cfg 字段名，诚实留空） |
| v1 → v2 迁移 / 升级后补解析 / 补解析后再扫 | 0.36 秒 / 31.1 秒（重解析 2035 行）/ 182 毫秒 |
| 标注导出 40 条 / 导入试算 / 导入真写 | 23 ms（6.3KB）/ 38 ms / 45 ms，试算与真写逐项一致 |
| 批量收藏 1023 项（3 片 ×500） | 服务端与界面计数一致（收藏 1023） |

真实库里**没有 `.webm` / `.mkv`**（532 个视频全是 mp4）。EBML 解析这一轮**补上了**——没有真实样本就用 ffmpeg 现造 webm / mkv 并与 ffprobe 对账验收，属于向前补齐能力（VHS 可以输出 webm），覆盖率数字不变，我不会把它写成"提升"。756 张 `.jpg` 全是无 Exif / XMP / C2PA 标记的 `sha256_*` 下载图，所以 JPEG 元数据解析仍然**明确不做**。
