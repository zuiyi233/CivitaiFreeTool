# v2.6.32 · AI 自动化面 + 资源库自动化，已下载模型不再白传

这一版把「AI / 脚本驱动这个工具」从只能点界面变成一套可自描述的 HTTP 面，并沿着真实调用链路修掉几个会让「下载成功」变成假象的缺陷。同时，资源库补上了自动化入口，`_评论.txt` 也终于会跟着模型一起改名。

## 这版做了什么

| 方向 | 内容 |
|---|---|
| AI 自动化 | 先落 28 个 `/api/automation/*` 端点，随后扩到 batch、字段投影、move / rename / fs、storage/migrate、tasks/repair、history 清理 |
| 可靠性 | 已存在模型 `skipped=exists` 不再白传；收尾未完成不再假失败；外部改配置 1s 内生效；视频扩展名跟随源；`.part` 清理漏判修复 |
| 资源库 | 新增 `gallery` 只读查询 + 操作 + 扫描端点，收藏 / 标签 / 删除可脚本化 |
| 归档细节 | `_评论.txt` 跟随 `rename_to_civitai` 改名，不再留在旧名前缀下 |

## AI 自动化接口能力

全部复用既有 `Api` 与桥接口，不复制下载、分流、归档逻辑；端点清单由 `GET /api/automation` 与 `GET /api/automation/schema` 自描述（配置键类型 / 默认值 / 可选值、词表、类型→目录映射）。

- **发现与计划**：`/schema`、`/plan` 干跑、`/resolve` 追加全部版本清单，先挑版本再下载。
- **执行与观测**：`/download` 支持 `url|urls|model_id+version_id|file_ids`，可阻塞到终态并顺带校验；`/state`、`/tasks`（`wait`）、`/events`（带 `seq` 增量）、`/history`、`/logs`、`/extension`。
- **一次跑一组**：`POST /batch` 最多 50 条本层调用，逐条带 `http_status`，batch 本身恒 200，`stop_on_error` 可控。
- **字段投影**：列表 / 详情端点支持 `fields=`（含 `info.routed_dir` 这类点号路径），实测 `/library?limit=200` 载荷 56.6KB → 38.3KB（-32%）。
- **文件与目录**：`POST /move` 移动模型 / 任务落点 / 历史记录（只接受已存在的绝对目录，不代建）；`POST /rename` 单文件与批量改名（preview 只算不改）；`GET /fs` 只读目录浏览（列盘符与一层目录，不读文件内容），补上「AI 拿不到 pick_dir 结果」的缺口。
- **运维与修复**：`POST /storage/migrate`（必须 `confirm:true`）、`POST /tasks/repair`（按 stage 重跑收尾，带完成信号）、`POST /history` 清理指定记录（`remove` / `clear` / `preview`）。`library/op` 扩到 organize / rename-c / rename-preview / translate-descs / cleanup。
- **排障**：`/connectivity`（DNS 污染特征、系统代理与应用代理的差异）、`/prompts`、`/verify`。
- **错误统一 `{ok:false,msg,hint}`**：hint 直接给下一步动作，例如 400 时提示先 `POST /resolve` 看有哪些 `file_id`。

## 可靠性与修复

1. **已存在的模型不再白传**：`POST /download` 发现目标文件已在时返回 `{skipped:"exists", task:null}`，并用 hint 指向 `force:true`。实测对一个已下载模型调用，此前会重传 284MB、覆盖同名文件、拖慢队列；现在 5.8s 返回、0 传输、不建任务。预判只看单条 `url` / `model_id`，`urls` / `file_ids` 批量与关闭分流时算不出落点，行为同旧版。
2. **收尾未完成不再假失败**：`status=done` 只代表传输结束，收尾线程还在写 sidecar。任务行新增 `postprocess{done,stages,finished_at}`，`download(wait=1,verify=1)` 在 verify 前等它（30s 预算），9.1MB 模型的「下载成功却判失败」不再复现。
3. **收尾失败不再静默**：元数据 / 封面 / 视频 / 旧版清理的失败写 `error.log` 并挂到 `postprocess_errors`，下载页状态列显示「收尾未完成」——不再只看到「已完成」而库里缺名字 / 类型 / 海报。收尾失败可用 `POST /tasks/repair` 按 stage 重跑，不必手工分项处理。
4. **verify 口径拆开**：`ok` 只看文件本身是否可用，`bundle_ok` 看配置要求的附属文件是否齐全，`sidecars.expected_missing` 列出缺哪些。没配 API Key 时评论文件本就不会写、`metadata_format=civitai` 不写 `.json`，不再因此把成功判成失败。
5. **外部改配置 1s 内生效**：`save_config` 递增 `cfg_rev`，前端每 2 个周期轮询 `get_ui_flags` 并应用门禁字段（实测 1.0s，此前永不生效）。
6. **视频扩展名跟随源**：不再一律写成 `.mp4`，`.avi` / `.webm` / `.mkv` 存真扩展名；同时修 `_images_fill_targets` 的 `have_video` 分支可能指向不存在文件。
7. **`.part` 清理漏判**：`_cleanup_removed_part` 的引用判断只看还可能写的任务（pending / downloading / paused）。此前一个已完成任务占着同一目标路径也算「仍被引用」，对已存在模型重复下载后移除任务，实测 191MB 的 `.part` 被永久保留。`.part` 改名失败也不再假报 DONE：退避重试 4 次，仍失败转 ERROR 并说明完整内容在 `.part`。
8. **镜像站与扩展链路**：公开 API、下载链接、历史记录与图片页链接跟随 `site_domain`（此前硬编码 `civitai.com`，只有镜像站可达时整条超时）；扩展离屏文档只有 `chrome.runtime`，content 消息改由 background 代发并加 ping/ready 握手，归档不再卡在「准备归档」；`plan` 不再无条件多拉一次 `/v1/models`（实测 2.3s），版本响应自带 `model{name,type}`。
9. **历史清理只删记录**：`POST /history` 的 `remove` / `clear` / `preview` 只清 `download_history.json` 与 `history_assets/`，**绝不删模型文件**；预览不落盘，未知 id 进 `missing` 不报错。实现同时摘掉队列里的同 id 终态任务并用有界墓碑拦住「删除瞬间还在路上的 `_notify`」，避免下次保存把记录写回；删除失败 / 中断记录时连带清理它的 `.part`，沿用既有归属校验。

## 资源库自动化

- `GET /api/automation/gallery`：资源库列表查询。
- `GET /api/automation/gallery/item`：单条详情。
- `GET /api/automation/gallery/tags`：标签查询。
- `POST /api/automation/gallery/op`：收藏 / 加摘标签 / 删除。
- `GET/POST /api/automation/gallery/scan`：扫描入口。

删除走系统回收站，且只回收媒体本体、不连带 sidecar，与界面「删除只回收媒体本体」同口径。

## 评论文件跟随改名

`_评论.txt` 已加入 `rename_to_civitai` 的 sidecar 名单：按 C 站名改名时评论文件跟着换前缀，改名失败回退时也一起回退，不再留在旧名前缀下。

## 从 v2.6.30 升级：v2.6.31 的内容也一并在内

这次 Release 同时包含 v2.6.31 的改动（扩展↔桌面端链路修复、非 PG 示例图与提示词、评价/评论归档），细节见 [v2.6.31 说明](v2.6.31.md)。从 2.6.30 升级的用户只替换 EXE 即可拿到两版内容。

## 升级方式

只替换 EXE，配置、下载任务、历史、模型与缓存都保留，不需要重新配置。

浏览器扩展本版**没有功能改动**：仓库在 v2.6.31 时仍是 2.2.0，之后已升到 2.3.0（固定扩展 ID）。已加载 2.3.0 的用户**无需重新安装**；仍在 2.2.0 或更早的用户需要按扩展 README 做一次「移除旧条目 → 加载新目录」——2.3.0 起扩展 ID 固定为 `cljlgpakghbofcdjbimchcmefdfnfdii`，Chrome 会把新旧当成两个扩展。此后每次更新只需点「重新加载」，`chrome.storage` 与 IndexedDB 里的提交记录不再随目录变化清空。

## 已知边界

- **评论正文仍需要已登录的 C 站标签页**：带 API Key 对评论计数一律返回 0，纯桌面端流程只保证评价；「登录会话能拿到非空评论正文」至今没有被任何路径实测证实。
- **评价最多 250 条**（5 页 × 50）：热门版本远超此数，超出时文件里如实写「站点共 N 条，本次只保存前 250 条」。
- **不做历史回填**：只有新完成的下载才生成评论文件；`/history` 清理也只删记录与历史缓存，不动模型。
- **自动化端点仅本机信任**：面向本机 AI / 脚本，不额外做鉴权，不要暴露到公网。
- **`skipped=exists` 只覆盖单条 `url` / `model_id`**：批量与关闭分流时不预判，仍会按旧行为下载；需要强制重下时显式传 `force:true`。
- **资源库删除不可从软件内撤销**：走系统回收站，能否恢复取决于回收站状态。
