# v2.7.0 · MCP 接入层：文本与多模态各走一条最优路径

这一版把 AI 接入从「HTTP 自动化面」推进到 **MCP 是一等公民**。外部 AI（Qoder、Claude Desktop、
Cursor 等）通过 `CivitaiFreeToolMCP.exe` 直接拿到工具、资源与提示词；纯文本模型不会被图片字节
挤爆上下文，多模态模型则能直接看到封面、示例图、视频首帧与联系表。MCP 之外再补两条同契约的
本地旁路：**OpenAPI 3.1** 给不支持 MCP 的 Agent 平台，**SSE 事件流** 让任务/弹层变化主动推送。

## 架构：一份契约，多路投影

```
ai_contract.py          单一事实源：29 工具 + 21 类事件 / Schema / 工具集 / 错误码 / 指南
   ├── CivitaiFreeToolMCP.exe      stdio + Streamable HTTP（MCP）
   ├── /api/automation/*           HTTP 投影（脚本 / 非 MCP 客户端）
   ├── /api/automation/openapi.json OpenAPI 3.1 + 每工具 POST 别名
   ├── /api/automation/events/stream SSE 领域事件流
   └── skills/civitai-free-tool    安装、recipes、安全与排障
```

MCP 侧车不直接操作磁盘：它把工具调用送给本机桥 `POST /api/automation/tool`，
由 `ai_tools.py` 复用既有的下载、分流、校验、资源库逻辑。因此 MCP 与 HTTP 的行为逐字节一致，
不会出现「MCP 能下、界面不能下」的分叉。

## 工具集

| 工具集 | 数量 | 内容 |
|---|---|---|
| core | 19 | 能力发现、状态、搜索、解析、下载、任务控制、文件选择、弹层关闭、校验、修复、模型库、资源库查询/打标、工作流分析、`describe_model`、诊断 |
| vision | 5 | `view_model` / `view_gallery` / `view_workflow` / `contact_sheet` / `inspect_image` |
| admin | 5 | 文件移动/改名、配置写入、历史清理、存储迁移、资源库删除 |

`--toolsets core,vision` 按需暴露；admin 默认不加载。destructive 工具（dedupe-delete / cleanup /
storage migrate / gallery delete）带 `destructiveHint` 且必须 `confirm:true`。

`cft_dismiss_ui` 专门处理「人需要引导、AI 不需要」，但范围不只新手引导：确认框、下载文件选择、
下载完成移动询问、设置未保存、受限提示、结果窗、详情抽屉、图片查看器都能一键关闭。
关闭确认框等于取消，绝不自动确认危险操作；下载文件选择关闭等于取消本次下载。
`permanent=true` 只把新手引导设为不再自动弹；`cft_get_state` 的 `blockers` 会按前端上报的
可见弹层直接给出修复动作。

## OpenAPI 3.1 + SSE：MCP 之外的两条本地旁路

- `GET /api/automation/openapi.json?profile=text|vision|admin|all` 从 `ai_contract.py`
  运行时生成；默认 text 19 个操作。每个工具同时有真实执行路径
  `POST /api/automation/tool/{name}`，body 直接填 arguments，与通用 `/tool` 共用同一条执行链。
  可直接导入 Dify / n8n / LangChain / Open WebUI 等本地函数调用平台。
- `GET /api/automation/events/stream` 提供 SSE：`state.snapshot` 首帧、15 秒心跳、
  `Last-Event-ID` 重放、`stream.reset` / `stream.overflow`。事件源由 `automation_events.py`
  每秒做只读快照差分，不改下载器任务状态机；可推任务、文件选择、扫描、弹层和配置变化。
- 事件目录同样进入契约（`ai_contract.EVENTS`，21 类），并由 `cft_capabilities.caps.events`、
  OpenAPI `x-cft-events` 与文档共用；`types=all` 才会看到调用日志事件，默认只推领域事件。
  下载文件选择走变更日志而不是电平比较，因此「弹窗一闪而过」也能被订阅端捕获；
  只在两次采样之间出现又结束的任务会补发 `task.created` + `task.finished` 一对。
- 两条旁路都只监听 `127.0.0.1`：OpenAPI `servers` 只回显回环 Host，远程 Agent / 云端 GPT
  连不上是预期边界，不通过暴露端口绕过。

## 打开的模型标签页（不再模拟键鼠）

浏览器扩展本来就能列出全部 C 站模型页；这一版把同一份只读数据交给 Agent：

```
扩展 background（tabs 权限）
  → POST /api/ext/tabs（标题/URL/模型版本 ID，去抖 + 每分钟心跳）
  → 桌面桥内存索引（不落盘）
  → cft_browser_tabs（只读搜索）
  → cft_download_model（已有下载链）
```

```bash
# 搜已打开页面（不需要截图、点击、切标签）
curl -s "http://127.0.0.1:47531/api/ext/tabs?q=wallpaper"
# 或走契约工具
curl -s -X POST http://127.0.0.1:47531/api/automation/tool/cft_browser_tabs \
  -H 'Content-Type: application/json' -d '{"query":"wallpaper"}'
# 找到后用已有下载工具
curl -s -X POST http://127.0.0.1:47531/api/automation/tool/cft_download_model \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://civitai.red/models/1264662/live-wallpaper-style?modelVersionId=3351608","wait":true,"verify":true}'
```

只收 C 站模型详情页；普通网页来源 403；最大 512KiB / 2000 行；超过 150s 未推送标
`stale`，与“没有标签页”分开。索引只在内存，桌面端退出即清空；扩展弹层 UI 不变。
完整契约见 [`docs/browser-tabs-bridge.md`](../browser-tabs-bridge.md)。

## MCP 常驻与一键接入

冻结版桌面端启动后会自动拉起同目录 `CivitaiFreeToolMCP.exe`：

```text
--http --port 47532 --toolsets core,vision,admin --exit-with-bridge
```

- 47532 已被占用则跳过；侧车在桥连续不可达约 30s 后自行退出，不留孤儿进程。
- 源码运行与测试不会自动拉起；`mcp_http_autostart=false` 或 `CFT_NO_MCP_HTTP=1` 可关闭。
- token 仍只写 `%LOCALAPPDATA%\CivitaiFreeToolWeb\mcp_http_token.txt`，终端/日志不回显。

一条命令合并客户端配置（先备份，保留其它 server）：

```bash
python scripts/mcp_setup.py --client cursor --apply                 # stdio
python scripts/mcp_setup.py --client claude --transport http --apply
```

`cft_capabilities` 现在同时回答：扩展是否在线、扩展版本、标签页索引新鲜度、
MCP HTTP 是否在跑、token 文件在哪（只给路径）。AI 不再靠猜。

## 下载落点可判定

`plan` / `resolve` / `download` 的每个文件与单条结果新增只读 `placement`：

```json
{"dest_dir": "D:/models/loras/demo", "routed_dir": "D:/models/loras/demo",
 "folder": "loras", "under_models_root": true,
 "status": "routed", "hint": ""}
```

- `status`：`routed` / `under_root` / `outside_root` / `pending`。
- 分流关闭时也按 `download_target_dir` / `download_dir` 预判已存在文件，避免重复下载。
- `cft_diagnostics storage` 增加 `candidates` / `suggested_root`：只从已配置目录自身或直接上级
  识别 ComfyUI 模型根，不扫整盘。
- **只报告**：不自动搬文件、不自动改配置、不新建未注册的类型目录。

## 扩展开发态（免打包）

```bash
python scripts/dev_extension.py link     # .tools 下已加载副本 → 源码 junction（先备份）
python scripts/dev_extension.py watch    # 改源码 → 桥置 dev_reload_at → 扩展下次心跳自重载
```

- `manifest.key` 不变，扩展 ID 与存储不变；不再压缩、重新选择目录。
- 已见时间戳存 `storage.local`，不会因心跳反复重载。
- 内容脚本改动：Chrome 2.7.0 起由后台 `ping` 探测后自动注回（见下一节），Firefox 临时附加组件每次重启仍需手动载入一次。
- 完整说明见 [`docs/extension-dev-mode.md`](../extension-dev-mode.md)。

## 两条模态路径

**文本模型**：`cft_describe_model` 在一条返回里给出模型信息、示例图的 prompt / negative / steps /
sampler / seed、附属文件清单与下一步动作；列表类工具支持 `fields=`，`mode=text` 会递归剥掉
`b64` / `preview_b64` 与 `data:` URL，避免图片字节进入上下文。

**多模态模型**：vision 工具返回 MCP `ImageContent`，同时兼容 OpenAI `image_url` 与 Anthropic
base64 image。图片本地优先，视频只取首帧，contact sheet 把最多 24 张缩略图拼成一张并附 mapping。
硬上限：单图 3MB、总量 8MB、最多 8 张、单边 1536px；超出部分进 `omitted` 并说明原因。


## 浏览器扩展：模型下载状态与工作台

Chrome 扩展升到 **2.6.1**、Firefox 扩展升到 **1.7.1**。扩展现在不仅能回答“当前打开的模型页，本机到底有没有”，
还把浏览、检查更新、下载完成串成一条链路：

- 桌面端新增 `POST /api/model/status`：合并模型库扫描、下载历史、活动任务与 `model_updates.json`，批量返回
  `downloaded / update_available / downloading / other_version / not_downloaded / unknown` 六态。旧历史行没有
  `model_id/version_id` 时，从 `history_assets/<id>.json` 快照回填（按 mtime 缓存）。
- Chrome：模型页右下角状态胶囊、逐标签工具栏徽章、弹层行徽章 + “下载状态”筛选 + 汇总；批量归档期间不占用徽章。
- Firefox：弹层内提供同样的行徽章、筛选、汇总、「只选未下载」与「下载选中项的新版」；与 Chrome 共用逐字节相同的
  `lib/model-status.js`，不注入网页、不申请新权限。
- 动作闭合：「只选未下载」只勾确认未下载的行；「下载新版」发 `update.latest_url`，不是页面里的旧版本；普通发送命中
  已下载/有更新的行会先确认。
- 诚实口径：扩展只发模型/版本 ID 与清洗过的页面 URL，不读 Cookie、API Key 或正文；状态缓存 2 分钟（下载中）/ 5 分钟
  （其余），CFT 离线或桌面端过旧时显示上次缓存/需升级，不把“没查到”说成“未下载”。
- **列表页 / 图片页徽章**：C 站 `/models` 卡片与图片/帖子页的模型链接直接标 `✓ 已下载 / ↑ 有更新 / … 下载中 /
  ◐ 其他版本 / ↓ 未下载`；unknown 不贴，列表页查询不写工具栏徽章。
- **Chrome 侧边栏**：`chrome.sidePanel` 常驻同一套工作台，侧栏页不自动关闭；Firefox 不做侧栏。
- **一键检查更新**：只对当前列表里模型库命中的本地路径调用桌面端 `mm_check_updates`，显示进度并在完成后刷新状态，
  不自动下载；缺 Key、正在跑、超时各有独立文案。
- **完成通知 + 打开目录**：普通提交批次的任务到终态发 Chrome 通知（持久化去重），后台守望最多 2 小时且全部落地即停；
  桌面新增 `POST /api/reveal`，只接受模型库/下载历史/活动任务已登记的路径，未登记返回 403。Firefox 任务行同样能打开目录。
  批量归档有自己的进度面板与徽章，暂不逐模型发系统通知。
- **SHA256 身份回退**：C 站文件哈希随状态请求发送，桌面用模型库侧车与历史哈希回退，识别改名/换目录的同一文件；
  文件已不存在则不猜，活动任务不作为“已下载”证据。
- **页面历史**：“看过但未下载”清单只存本机扩展记录（URL/标题/时间，30 秒去重、最多 500 条），可一键清除，
  与下载历史/模型文件无关。

验收：`tests/test_model_status.py`、`test_reveal_path.py`、`test_browser_bridge.py`、`test_download_history.py`、
`test_model_status_background.cjs`、`test_model_status_ui.cjs`、`test_firefox_parity.cjs`、
`chrome-extension/content/list-status.test.cjs`、`chrome-extension/lib/model-status.test.cjs`、
`chrome-extension/lib/enrich.test.cjs` 全部通过；原有 `test_popup_integration.cjs` / `test_extension_batch.cjs` 无退化。

### 免点击自动显示（Chrome 2.7.0 / Firefox 1.8.0）

用户反馈的是同一件事：C 站页面上看不到"这个模型本机有没有"，图标也没有徽章，**必须点开弹层才看得见**。
逐条对着代码确认到三条根因（设计全文见 `docs/extension-status-autoshow.md`）：徽章只从 `cftModelStatusV1`
缓存补、而那份缓存只有弹层跑过一轮批量查询才会被填；MV3 扩展重载会把已打开标签页里的 content script
一起杀掉，不刷新页面就没人画胶囊；心跳只推标签页索引，没有周期性的状态刷新。

- **后台自己查**：新增 `refreshOpenTabsStatus()`，在 `onStartup`、`onInstalled`（安装/更新/重载都算）与新登记的
  `cft-status-heartbeat`（`periodInMinutes: 2`）三处触发。一轮最多取 60 个未休眠的 C 站模型页标签，
  同一批 1.5 秒内合并成一次请求（启动+更新+心跳常挤在同几秒），结果点亮逐标签徽章并推给页面已有胶囊。
- **Chrome 免刷新补脚本**：先 `tabs.sendMessage({type:'ping'})` 探测页面里还有没有接收者，确认没了才用
  `scripting.executeScript({files})` 把 **manifest 自己声明的那几个文件**注回去（清单直接读 manifest，不写第二份），
  `insertCSS` 同理；跳过休眠标签与非 C 站页面，绝不 `func`/`code` 执行任意代码，脚本侧再加
  `window.__cftModelPageInjected` 幂等守卫。这是本次唯一新增的权限，用途写进扩展 README 的隐私一节。
- **Firefox 只镜像不需要注入的那一半**：不申请 `scripting`（它没有 `content_scripts`，要了也换不到功能），
  同一套批量查询 + 逐标签 `setBadgeText({tabId})` + Firefox 才有的 `setBadgeTitle({tabId})`；新开的模型页
  先按缓存点亮徽章（只读 storage、零网络请求），不等心跳。页面胶囊在 Firefox 确实做不到，README 差异表
  那一行写的是"没有"，不伪造平价。
- **两条同时收紧的口径**：状态请求发 `CftTabs.modelLink()` 清洗过的 URL，不发标签页原始地址（原始地址可能
  带着 `token=`，既不该进请求体也不该进桌面日志）；桥没连着（或桌面端太旧）时 `entryForItem` 用缓存里那一版
  结论并打 `offline` 标记，徽章仍是 `✓` 而不是塌成 `?`。同时把「没有徽章＝还没判定过」与 `?`（问过没有结论）
  分开写进文档。
- **两条只有真 Chrome 才暴露的问题**：① `chrome.runtime.reload()` 之后浏览器不保证把 `onInstalled`
  交给新的 service worker（它只等事件把 SW 叫醒），所以唤醒不能只挂在 `onInstalled`/`onStartup` 上——
  模块级新增 `bootWake()`：每次 SW 醒来都补登记心跳，且只有「状态心跳闹钟不见了（刚被重载/更新过）」
  或「`cftBootWakeAtV1` 超过 90 秒」才补一整轮，空闲重启安静跳过。
  ② `executeScript({files})` 注入的是**同一个隔离世界**，`lib/util.js` 顶层的 `const _utf8Len`
  第二次声明直接抛 `SyntaxError: Identifier '_utf8Len' has already been declared`，整批脚本静默失效——
  也就是说"免刷新补回胶囊"这条链在真机上根本没跑起来，而 vm 里假 `executeScript` 永远发现不了。
  注入文件的顶层声明已全部改成 `var`/`function`，并加了两道闸：静态不变量（manifest 注入清单里不许出现
  顶层 `const/let/class`）+ 真加载回归（重复注入后页面仍只有 1 个胶囊、0 条页面脚本错误）。
- **真机验收**（`CFT_EXT_REAL=1 node tests/test_extension_real_load.cjs`，真 Chrome + 用户本机桌面端）：
  只装载扩展、**没点图标也没开弹层**，打开 `[MMH3] Anime Shift` 页面即自己出现
  `✓ 已下载 · v1.0`，与 `POST /api/model/status` 的 `state=downloaded` /
  `local.path=D:\ComfyUI_Mie_2026_V8.0\ComfyUI\models\loras\MMH3-AnimeShift-V1\…` 一致；后台一推
  `modelStatusPush`，页面不刷新（主世界标记仍在）就把陈旧文本改成正确状态；`chrome.alarms.getAll()`
  里 `cft-status-heartbeat` 确实按 2 分钟在册，storage 里有 `cftBootWakeAtV1`。
  `runtime.reload()` 那一刻不在这套 harness 里跑：实测 Playwright 临时 profile 重载后扩展 SW 再也不回来
  （40 秒内 SW 列表与 `serviceworker` 事件都空，新开标签也唤不醒），所以重载那一轮改由 vm 冷启动用例钉。
- **测试**：`tests/test_extension_batch.cjs` 新增/改写 6 组（批量补脚本+点亮徽章、安装与启动共用同一轮在途查询、
  有回音不重复注入、60 个标签上限），并把权限不变量改成更窄的承诺——Chrome 必须有 `scripting`、Firefox 必须没有、
  `executeScript` 不许带 `func`/`code`、`<all_urls>` 仍然禁止；两边各钉一条"请求体里没有 token"。
  `tests/test_firefox_parity.cjs` 新增 §3.7（真 `background.js` 在 vm 里跑）：免点击点亮、离线不降级、
  导航即按缓存出徽章且零请求、批量上限。

本版发布物为 `CivitaiFreeToolWeb.exe` 与 `CivitaiFreeToolMCP.exe`；升级只替换 EXE，
数据目录（配置 / 任务 / 历史 / 缓存）不变。浏览器扩展同时发布 Chrome / Edge **2.7.0** 与
Firefox **1.8.0**（ZIP 资产名不带版本号，按扩展 README 原地「重新加载」覆盖升级）。

## 安全边界

- MCP HTTP 与桌面桥都只监听 `127.0.0.1`，不要端口映射到公网。
- HTTP 使用 Bearer token；token 只写本机文件或从 `CFT_MCP_TOKEN` 读取，不写日志、不回显。
- 冻结版自动拉起的 MCP 侧车只启动同目录官方 EXE；47532 被占则跳过，桥断约 30s 自退。
- 扩展开发接口只改「何时重载」，不执行任意代码、不传页面数据；网页来源被 Origin 白名单拒绝。
- 下载落点诊断只读；不自动移动文件、不自动改配置、不新建未注册的类型目录。
- 写操作走白名单与 `confirm:true`；删除走系统回收站，资源库删除不连带共享 `.json`。
- 桥的 POST body 上限：普通端点 1MB，`/vision/analyze` 与 `/api/automation/tool`（MCP 图片上传入口）
  8MB；超限返回 413 + 明确上限。
